mt: User ManualA keyboard-driven terminal workspace launcher

Overview #

mt is a keyboard-driven TUI (terminal UI) that turns your most-used commands into a fast, navigable menu. No mouse. No memorizing flags. Navigate a three-pane interface, press Enter, see output inline.

Common uses:

  • Launch macOS apps without leaving the terminal
  • Run Docker compose, git, and dev-server commands from a single interface
  • Trigger multi-step deploy pipelines as a sequence: Build → Test → Deploy
  • Run multiple commands in parallel with Space + Enter
  • Execute commands on remote servers over SSH

Installation #

Download a release

Each tagged release on the GitHub releases page has ready-built archives for macOS (Apple Silicon and Intel) and Linux (x86-64 and ARM64), plus a checksums.txt. The macOS Apple Silicon archive also contains mt-apple-bridge.

tar -xzf mt-v1.0.0-darwin-arm64.tar.gz
sudo install -m 0755 mt-v1.0.0-darwin-arm64/mt /usr/local/bin/mt
mt --version

go install

Requires Go 1.25 or later (the version in go.mod).

go install github.com/mrwalker511/mt@latest

This places the mt binary in $GOPATH/bin (usually ~/go/bin). Make sure that directory is on your $PATH.

Build from source

git clone https://github.com/mrwalker511/mt
cd mt
make build   # produces ./mt in the project root

Other make targets:

CommandAction
make buildCompile binary to ./mt, stamped with the version from git describe (shown by mt --version)
make checkRun the same checks as CI: gofmt, go vet, staticcheck, and tests with the race detector
make installInstall mt to /usr/local/bin/mt
make testRun test suite
make vetRun go vet
make cleanRemove compiled binary
make apple-bridgemacOS Compile Swift bridge to ./mt-apple-bridge (requires macOS 26 + Xcode CLI tools)
make install-apple-bridgemacOS Install bridge binary to /usr/local/bin/mt-apple-bridge

Quick Start #

Run mt from any directory:

mt

If no config file is found, built-in defaults are shown (see Default Workspaces).

3-pane layout

┌──────────────────┬──────────────────────┬──────────────────────────────────┐ │ DOMAINS │ TARGETS & ACTIONS │ LIVE STATUS / INFO │ │ │ │ │ │ > Outlook │ > Open Outlook │ Press [Enter] to launch Outlook │ │ Word │ New Email │ │ │ Excel │ Open Inbox │ │ │ Microsoft Edge │ Open Calendar │ │ │ VS Code │ New 30-Min Meeting │ │ │ Terminal │ … │ │ │ Infrastructure │ │ │ │ Context/Git │ │ │ └──────────────────┴──────────────────────┴──────────────────────────────────┘ ⏎ Run ␣ Select ⇥ Pane / Ask AI c Copy ⌫ Clear ? Keys q Quit
  • Left pane: Domain list. Arrow keys or j/k move the cursor. Domains group related targets (e.g. "Outlook", "Infrastructure", "Context/Git").
  • Middle pane: Target list for the selected domain. Press Enter to run, Space to toggle multi-select.
  • Right pane: Command output, live status header, and hints. Scroll with j/k when focused here.

First steps

  1. Use ↑ / ↓ to pick a domain, then press → or ⇥ to move focus to the middle pane.
  2. Use ↑ / ↓ to pick a target, or just click it.
  3. Press ⏎ Return (or double-click the target) to run it. Output appears in the right pane. Press ⎋ Esc to stop a command that keeps running.
  4. Press c to copy the output, just like ⌘C.
  5. Press ? at any time for the key reference, and q to quit.

Press ? inside mt for a compact reference, or run mt --keys in a shell to print the full list.

Configuration #

File locations

mt uses the first of these that exists:

  1. Folder config: ./mt.yaml in the folder you start mt from, if that folder is trusted (see below).
  2. User config (platform-dependent):
    • macOS  ~/Library/Application Support/mt/config.yaml
    • Linux  ~/.config/mt/config.yaml

If neither exists, built-in defaults are used. To create your own config:

# macOS
mkdir -p ~/Library/Application\ Support/mt
cp mt.yaml.example ~/Library/Application\ Support/mt/config.yaml

# Linux
mkdir -p ~/.config/mt
cp mt.yaml.example ~/.config/mt/config.yaml

Trusting a folder's ./mt.yaml

A ./mt.yaml can run any command, so mt only loads one from a folder you have trusted, much like VS Code's workspace trust. Without that, cloning a repository and starting mt inside it could hand your keyboard to whoever wrote the repository's mt.yaml.

cd ~/projects/myapp
mt --trust      # mt will now load ./mt.yaml here
mt --untrust    # stop trusting this folder

In a folder that is not trusted, mt ignores ./mt.yaml, loads your user config instead, and shows "Ignored ./mt.yaml: this folder is not trusted". Trusted folders are listed one per line in ~/.mt/trusted (readable only by you); symlinks are resolved, so a folder is recognised however you reach it. Trust is per folder, not per file version, so editing a trusted mt.yaml (and pressing r) keeps working.

World-writable files are refused Config files, including included ones, must not be world-writable. mt refuses to load them if they are.

YAML structure

# Single-workspace config (simplest form)
domains:
  - name: "My Project"
    targets:
      - name: "Start Server"
        status: "Press [Enter] to start"
        run: npm run dev
      - name: "Run Tests"
        run: npm test
# Multi-workspace config
workspaces:
  - name: "Microsoft"
    domains:
      - name: "Outlook"
        targets:
          - name: "New Email"
            run: open ms-outlook://compose
            launch_msg: "Opening new email…"
  - name: "Dev"
    domains:
      - name: "Context/Git"
        targets:
          - name: "Git Status"
            run: git status

Writing commands: run and cmd

run: takes a command the way you would type it in Terminal. mt splits it into words when the config loads and runs the program directly, exactly as if you had written the equivalent cmd: list.

You writemt runs
run: git log --oneline -n 10["git", "log", "--oneline", "-n", "10"]
run: open -a "Microsoft Word"["open", "-a", "Microsoft Word"]
run: git commit -m 'Fix the "login" bug'["git", "commit", "-m", "Fix the \"login\" bug"]
run: echo My\ Folder["echo", "My Folder"]

Quoting rules match a shell: whitespace separates words, 'single quotes' keep everything literally, "double quotes" allow \" and \\ escapes, and a backslash outside quotes escapes the next character.

There is no shell Pipes (|), &&, ;, redirects (>, <), $VARS, backticks and a leading ~ would only be passed to the program as literal text, so mt rejects them when the config loads and names the target. Quote them to pass them literally (run: echo "a | b"), or ask for a shell explicitly: 
- name: "Count Go files"
  cmd: ["sh", "-c", "ls *.go | wc -l"]

On SSH targets the rules differ: the run: string goes to the remote shell unchanged, so shell syntax is allowed there.

Use cmd: when an argument is long or awkward to quote, such as a multi-line AppleScript passed to osascript -e. YAML note: if a run: value starts with a quote or contains : or #, wrap the whole value in the other kind of quotes, e.g. run: '"/Applications/My App.app/Contents/MacOS/app" --flag'.

Field reference

FieldRequiredDescription

Typos are caught. An unknown key is a config error naming the file, line and key, with a suggestion when one is close, e.g. "mt.yaml: line 6: unknown key "comand" (did you mean "cmd"?)". A config with an error falls back to the built-in defaults (or, on reload, keeps the previous config) and shows the message.

Multi-workspace

Wrap your domains in a workspaces: block to switch between independent contexts with [ / ], or jump straight to one with 1–9 (in config order). Each workspace has its own domains, targets, run history, and output cache.

workspaces:
  - name: "Work"
    domains:
      - name: "Apps"
        apps: ["Microsoft Outlook", "Microsoft Teams"]
      - name: "Dev"
        targets:
          - name: "Build"
            run: make build

  - name: "Personal"
    domains:
      - name: "Apps"
        apps: ["Mail", "Safari", "Spotify"]

Workspace switching resets cursor positions and clears multi-select. Per-target output is preserved per-workspace.

Apps shorthand macOS

The apps: key under a domain accepts a list of macOS app names. Each entry auto-expands to a full target that runs open -a <name>:

domains:
  - name: "Apps"
    apps:
      - "Microsoft Outlook"
      - "Microsoft Edge"
      - "Slack"
      - "Visual Studio Code"

Explicit targets: entries within the same domain come first; apps: expansions are appended after them.

Include directive

Split a large config into multiple files using include::

# ~/.config/mt/config.yaml
include:
  - work.yaml
  - ~/shared/team-tools.yaml

domains:
  - name: "Personal"
    targets:
      - name: "Check Mail"
        run: open -a Mail

Include rules:

  • Relative paths resolve relative to the file that declares them. A leading ~/ expands to your home directory.
  • All paths (after resolving symlinks) must remain within your home directory ($HOME). Paths outside $HOME are rejected as a security measure.
  • Circular includes are detected and silently skipped.
  • Included domains: are merged; included workspaces: are appended. Only the top-level file's llm: block is used.
  • A missing or invalid include file is an error: mt reports it and falls back to the built-in defaults rather than silently loading a partial config.
  • If the merged result has any workspaces:, top-level domains: are ignored. Use one form or the other.

Features #

Single command

The default mode. Navigate to any target with a run: or cmd: field and press Enter. Output appears in the right pane as the command produces it, with a banner such as Running… 12s ⎋ stop underneath. The view follows new output like a terminal does; scroll up to read earlier lines and it stays where you put it. Enter is ignored while a command runs. Press Esc to stop it (useful for commands that never exit on their own, such as tail -f).

You can move to other targets while a command runs; the banner then names the running target. When it finishes, its output is filed under the target that ran it, so you see it when you return to that target.

Output (stdout and stderr combined) is capped at 1 MB while the command runs; anything beyond that is discarded and a truncation notice is appended. Commands run without a terminal and with stdin closed, so interactive prompts will not work. If a command prints nothing and succeeds, the target's launch_msg is shown (or "(command completed, no output)").

Sequence

A target with a sequence: field executes named targets in order. If any step exits non-zero, the sequence stops immediately.

domains:
  - name: "CI"
    targets:
      - name: "Full Pipeline"
        sequence: ["Build", "Test", "Deploy"]

      - name: "Build"
        run: make build
      - name: "Test"
        run: make test
      - name: "Deploy"
        run: ./scripts/deploy.sh production

Output streams into the right pane as each step runs, with a ▶ Step name line before each step. Rules:

  • Checked before anything runs. If a step name matches no target (e.g. a typo), a step has no run:/cmd:, or a step is itself a sequence (nesting is not supported), the sequence refuses to start and says which step is wrong. A pipeline can never silently skip Test and go straight to Deploy.
  • Name lookup: a step is looked up in the sequence's own domain first, then in the workspace's other domains in order.
  • Stops at the first failure. The error names the step, e.g. step "Test": exit status 1.
  • Esc stops the current step and the rest of the sequence.

Multi-select parallel

Run multiple targets at the same time:

  1. Focus the middle pane (→ or l).
  2. Press Space to toggle each target you want to run. A ◆ marker appears before selected targets.
  3. Press Enter to run all selected targets in parallel.

Each target's output streams in under a === Target Name === header (a … marks one still running), the banner shows how many have finished, and each target gets its own ✓/✗ badge. Sequence targets can be selected too: their steps run in order while the other targets run alongside. If any selected target cannot run (no command, or a sequence with a bad step), nothing starts and the error names each problem; the selection is kept so you can fix it. After a run the selection is cleared. Esc stops all of them.

SSH targets

Set the host: field to run a command on a remote server:

domains:
  - name: "Production"
    targets:
      - name: "Deploy"
        host: "deploy@prod.example.com"
        run: ./deploy.sh --env production
        launch_msg: "Deploy started…"

      - name: "Tail Logs"
        host: "app@prod.example.com"
        run: journalctl -fu myapp

With host: set, mt runs ssh -o BatchMode=yes host <command>. SSH uses your existing key configuration (~/.ssh/config, ssh-agent); no credentials are stored by mt. BatchMode means ssh never waits for a password or passphrase that mt has no way to show: it fails straight away with a message such as Permission denied (publickey) instead of hanging. Load your key into the agent first (ssh-add). Set dir: to run the command in a remote directory. Commands that never exit, like the journalctl -f example above, keep running until you press Esc.

The remote shell interprets the command On an SSH target, the run: string is sent to the remote machine exactly as written, just as if you had typed it after ssh host. The remote shell interprets it, so pipes, quotes, globs and $VARS work there (e.g. run: journalctl -u myapp | grep -i error), and mt's local shell-syntax check does not apply. With cmd:, ssh joins the list with spaces before sending it, so you must add remote quoting yourself (cmd: ["ls", "'My Dir'"]). Prefer run: for SSH targets.
Host validation The host: value must match [a-zA-Z0-9][a-zA-Z0-9._@%-]*. Values starting with - or containing spaces are rejected at config load time to prevent SSH option injection.

Live status

Give a domain a live: command and its output appears above the right pane whenever that domain is selected:

domains:
  - name: "Context/Git"
    live: git status --short --branch
    targets: [...]
  - name: "Infrastructure"
    live: docker ps --format "{{.Names}} {{.Status}}"
    targets: [...]
  • live: is written like run: (quotes group words, no shell). Use sh -c '...' if you need a pipe.
  • The first 3 non-empty lines of its standard output are shown. If it fails or takes more than 3 seconds, the header is hidden.
  • Only the selected domain is polled: once when you select it, then every 5 seconds. A poll never starts while the previous one is still running, so a slow command (Docker Desktop stopped, a big repository) cannot pile up processes.

The built-in Context/Git domain shows Branch: main (3 modified) and the built-in Infrastructure domain lists running Docker containers. In your own config, domain names have no special meaning: add live: to whichever domains should have a header.

Output management

After a command runs, its output is shown in the right pane. Per-target output is cached in memory so navigating away and returning restores the previous result.

KeyAction

Cached output per target is bounded at 256 KB. Log files are written with exclusive creation (O_EXCL) to prevent race conditions.

Config hot-reload

Press r to reload your config file without quitting. This lets you edit mt.yaml in a separate terminal and instantly see the changes in the running mt session.

Hot-reload also re-reads the llm: settings. It resets cursor positions, clears selections, and clears cached output. If the new config is invalid, an error is shown and the previous config continues in use.

AI assistant

Press / to open the AI prompt bar at the bottom of the screen. Type a natural-language request (up to 500 characters) and press Enter. The configured LLM receives the names and first status line of every target in the current workspace, plus the current time, and must reply with exactly one of three actions:

LLM responseWhat happens
RUN:<target_name>Selects the named target (case-insensitive match) in the current workspace and runs it, exactly as if you had navigated to it and pressed Enter. Sequence targets work too.
CMD:["prog","arg",…]Shows the proposed command and waits. Press Enter to run it or Esc to reject it. Nothing runs without your confirmation. Useful for dynamically generated osascript commands.
INFO:<text>Displays a short text answer in the right pane

Example requests:

  • open outlook → runs the Open Outlook target
  • create a 30-min meeting with john@company.com tomorrow at 2pm → generates and runs an osascript that creates the event in Outlook
  • what does git stash do → returns a short explanation

Each request handles one action, so for multi-step work use a sequence target. A reply without a recognised prefix is shown as INFO text. Requests time out after 30 seconds. Press Esc to close the prompt bar or cancel an in-flight request. Requires an LLM provider (see LLM configuration).

LLM configuration #

The AI assistant supports five providers: LiteLLM (local proxy, default), llama.cpp (Metal-accelerated GGUF), MLX (Apple Silicon native, fastest), OpenAI (cloud), and Apple Foundation Models (on-device, macOS 26+). All providers except Apple speak the OpenAI /v1/chat/completions API. Switch with a single provider: line in your config.

LiteLLM proxy (default: port 4000)

LiteLLM acts as a unified gateway in front of any model backend (Ollama, vLLM, cloud APIs, etc.).

pip install litellm

# Start the proxy with any backend model
litellm --model ollama/llama3.1:8b
# or
litellm --model gpt-4o-mini   # requires OPENAI_API_KEY in env
llm:
  provider: litellm           # or omit: litellm is the default
  model: llama3.1:8b
  # base_url: http://localhost:4000   # default

llama.cpp + Metal GPU (port 8080) macOS

llama.cpp runs GGUF models entirely on-device using Apple's Metal GPU. On an M5 Max with 36 GB unified memory, --n-gpu-layers 99 offloads all transformer layers to the GPU.

brew install llama.cpp

# Gemma 4 27B (download from huggingface.co/bartowski/google_gemma-4-27b-it-GGUF)
llama-server -m ~/models/gemma-4-27b-it-Q4_K_M.gguf \
             --n-gpu-layers 99 \
             --ctx-size 32768 \
             --threads 10 \
             --port 8080
FlagValueNotes
--n-gpu-layers 99All layers → Metal GPURequired for full speed on Apple Silicon; set lower to fall back to CPU for layers that don't fit
--ctx-size 3276832 K tokensGemma 4 supports 128 K; raise as RAM budget allows
--threads 1010 threadsMatches M5 Max's 10 performance cores

Gemma 4 model size guide for 36 GB unified memory:

  • gemma-4-27b-it-Q4_K_M.gguf (~16 GB): best speed/quality balance
  • gemma-4-27b-it-Q8_0.gguf (~29 GB): highest quality, but tight on 36 GB
llm:
  provider: llamacpp
  model: gemma-4-27b-it   # informational label; server uses the loaded model
  # base_url: http://localhost:8080   # default

MLX: Apple Silicon native inference (port 8000) macOS

Apple's MLX framework compiles models for the unified memory architecture of Apple Silicon, typically delivering the fastest token throughput of any local option on M-series hardware.

pip install mlx-lm

# Gemma 4 27B 4-bit (~16 GB): recommended for M5 Max
python -m mlx_lm.server \
  --model mlx-community/gemma-4-27b-it-4bit \
  --port 8000

# GPT-OSS 20B 4-bit (~12 GB): faster, lighter
python -m mlx_lm.server \
  --model mlx-community/gpt-oss-20B-instruct-4bit \
  --port 8000

Models are downloaded automatically from Hugging Face on first run.

llm:
  provider: mlx
  model: gemma-4-27b-it-4bit   # informational label; server uses the loaded model
  # base_url: http://localhost:8000   # default

OpenAI / OpenAI-compatible cloud

llm:
  provider: openai
  model: gpt-4o-mini        # or gpt-4o, o1-mini, etc.
  base_url: https://api.openai.com   # override for vLLM, LMStudio, etc.
  api_key: sk-...           # or set OPENAI_API_KEY env var

Apple Foundation Models (on-device, no API key) macOS

Uses Apple's FoundationModels framework, available on macOS 26+ with Apple Intelligence enabled. Inference runs entirely on-device via the Neural Engine: no network request, no API key.

A small bridge binary (mt-apple-bridge) is required because Go cannot import Swift frameworks directly. Build it once from the repository root:

make apple-bridge            # compiles cmd/apple-llm/main.swift → ./mt-apple-bridge
make install-apple-bridge    # installs to /usr/local/bin/mt-apple-bridge

The bridge is code-signed with the com.apple.developer.foundation-models.inference entitlement required by the framework. Place the binary alongside the mt binary or anywhere in $PATH.

llm:
  provider: apple
  # bridge_path: /usr/local/bin/mt-apple-bridge   # optional; searched in PATH by default
Requires macOS 26+ and Apple Intelligence Enable Apple Intelligence in System Settings → Apple Intelligence & Siri. The bridge will print "FoundationModels is not available" if the device or OS does not support it.

Debug logging

Set debug: true under llm: to record every AI assistant interaction:

llm:
  provider: mlx
  model: gemma-4-27b-it-4bit
  debug: true

Each interaction appends a timestamped block to ~/.mt/logs/debug.log:

[2026-06-14T20:30:00Z] provider=mlx model=gemma-4-27b-it-4bit

git clone https://github.com/mrwalker511/mt
cd mt
make build                    # produces ./mt
make install                  # copies to /usr/local/bin/mt

Or install just the binary without source:

go install github.com/mrwalker511/mt@latest
# binary lands in $(go env GOPATH)/bin: ensure that's on $PATH

Config file location

mkdir -p ~/Library/Application\ Support/mt
cp mt.yaml.example ~/Library/Application\ Support/mt/config.yaml

A ./mt.yaml in the current directory takes precedence over the system config. Useful during development; avoid it in shared directories.

make apple-bridge             # compiles Swift → ./mt-apple-bridge (requires Xcode CLI tools)
make install-apple-bridge     # copies to /usr/local/bin/mt-apple-bridge

Requires macOS 26 and Apple Intelligence enabled. The bridge binary must reside alongside mt or anywhere in $PATH. Override the path with bridge_path: in your config.

Symlink note

On macOS, /tmp and system temp directories resolve through /private (e.g. /var/folders/… → /private/var/folders/…). mt handles this transparently: include paths are validated after symlink resolution so you will not see false "outside home directory" errors.

Security Model #

mt is a local single-user tool. Its trust boundary is the config file: whoever can write the config can run arbitrary commands as the user who runs mt. The security controls below harden that boundary.

Folder trust

A ./mt.yaml in the current folder is loaded only if you have run mt --trust in that folder; otherwise it is ignored with a notice and your user config is used. Starting mt inside a freshly cloned repository therefore never loads that repository's targets. Nothing runs until you press Enter in any case, but trust stops a hostile config from relabelling targets you rely on. See Trusting a folder.

SSH host validation

The host: field is validated at config load time against the pattern ^[a-zA-Z0-9][a-zA-Z0-9._@%-]*$. This rejects values starting with -, which SSH would interpret as option flags (the vector for ProxyCommand injection). A config containing an invalid host is rejected entirely and mt falls back to built-in defaults with an error message. SSH also runs with BatchMode=yes, so it can never sit waiting at a hidden password prompt.

World-writable config rejection

Before reading any config file (including files loaded via include:), mt checks the file permissions. If the world-writable bit (0002) is set, mt refuses to load the file. On a shared or multi-user system this prevents another user from injecting commands by modifying a config file they can write to.

If mt rejects your config with a "world-writable" error, fix it with:

chmod o-w ~/.config/mt/config.yaml

Include path restrictions

Include paths (after resolving symlinks) must resolve within your home directory ($HOME). This prevents a malicious project's ./mt.yaml from reading sensitive YAML files elsewhere on disk (e.g. ~/.kube/config, /etc/secrets.yaml). Symlinks that point outside $HOME are also rejected.

Circular include protection

Include chains are tracked by canonical path. If a file has already been loaded in the current chain it is silently skipped, preventing infinite loops.

Command execution safety

Local commands are always passed as argument arrays, never through a shell. cmd: ["git", "status"] calls exec.Command("git", "status"), not sh -c "git status". This means shell metacharacters (;, |, &, etc.) in arguments are treated as literals, not shell syntax. The exception is SSH targets, whose command is interpreted by the remote shell.

Commands proposed by the AI assistant (CMD:) never run until you confirm them with Enter.

Output and cache bounds

Command output is capped at 1 MB as it is read, so a runaway command cannot grow memory without limit. Per-target cached output is limited to 256 KB. This prevents runaway commands from exhausting available memory.

Log file safe creation

Log files are created with O_EXCL (exclusive creation), which fails if anything, including a symlink, already exists at the target path. This closes a TOCTOU race that could otherwise be used to overwrite an arbitrary file.

Log files are stored in ~/.mt/logs/ with mode 0640 (readable only by owner and group). The directory itself is created with mode 0750.

Goroutine and process cancellation

All commands and polling operations use a shared context.Context. Pressing q or Ctrl+C cancels the context, which kills any in-flight exec.Command processes. Esc cancels only the current run's child context, stopping the running command(s) while mt keeps going.

Troubleshooting #

Config errors

Error messageCauseFix
"file is world-writable" Config file has 0002 permission bit set chmod o-w <config-file>
"invalid ssh host" host: value contains illegal characters or starts with - Use format user@hostname or plain hostname
"path must be within home directory" include: path resolves outside $HOME or via a symlink that escapes $HOME Move the included file inside your home directory
"line N: unknown key "…" (did you mean "…"?)" A misspelled or unsupported key in the config Fix the key on that line; the suggestion is the closest valid key
"Ignored ./mt.yaml: this folder is not trusted" The folder has an mt.yaml but you have not trusted it Run mt --trust in that folder if you trust its config
"sequence "…": step "…" not found / has no command / can't be nested" A sequence: names a missing target, a target without a command, or another sequence Fix the step name or give the step a run:; nothing was run
"no domains or workspaces defined" Config file is valid YAML but has no content Add at least one domain with one target
"Config error (using built-in defaults): …" Config file (or one of its includes) was found but is missing, unreadable or invalid. The message after the colon gives the exact cause. Check YAML syntax; run cat config.yaml | python3 -c "import sys,yaml;yaml.safe_load(sys.stdin)"

Clipboard not working

The c key copies output using a platform clipboard tool:

  • macOS Uses pbcopy (built-in, always available)
  • Linux Tries xclip, then xsel, then wl-copy (Wayland)

On Linux, install one of these if copying doesn't work:

# X11
sudo apt install xclip
# or
sudo apt install xsel

# Wayland
sudo apt install wl-clipboard

SSH commands fail immediately

mt runs ssh with BatchMode=yes, so anything that would need typing (a password, a key passphrase, accepting a new host key) fails at once instead of hanging. Typical messages are Permission denied (publickey) and Host key verification failed. Ensure:

  • Your SSH key is loaded: ssh-add ~/.ssh/id_ed25519 (on macOS, ssh-add --apple-use-keychain remembers it)
  • The host is already known: connect once in a normal terminal with ssh user@hostname echo ok and accept its key
  • SSH config in ~/.ssh/config has the right settings for the host

Commands appear to hang

Some commands block waiting for stdin (e.g. interactive prompts). Since mt captures output without a TTY, the command may hang. Use non-interactive flags (e.g. docker exec -it → docker exec, git commit with -m). Press Esc to stop the command.

Terminal is too narrow

mt requires a minimum terminal width to render correctly. Widen your terminal window if you see a "terminal too narrow" message.

Hot-reload wipes run history

Pressing r resets all cursor positions and cached target output. This is intentional: the workspace structure may have changed. Run your commands again after reloading.
